# 模板多模型与工具适配

模板编辑采用方案 2：左侧管理模型连接，右侧保存工具适配规则。每个连接共享服务商账号、地址和协议，可以多选或输入多个模型 ID。每个模型保留独立的能力和推理偏好，密钥继续来自凭据库。

默认模型位于备注上方。首次添加模型时选中第一个模型，随后添加或调整模型不会改变默认项；删除默认模型后必须重新选择。后续连接默认收起，窄屏下工具适配移至连接配置下方。

## 各工具的规则

- Claude Code：选择一个 Anthropic Messages 连接，统一使用默认模型，或分别指定 Opus、Sonnet、Haiku。三个档位可以重复使用同一个模型。
- Codex：选择一个 OpenAI Responses 连接，勾选可用模型，单独指定启动默认模型及推理强度。生成受管理的模型目录并通过 `model_catalog_json` 引用；切换到普通单模型配置或官方入口时移除受管理的目录引用。
- Kimi / DSH：可以选择不同连接中的多个模型，指定工具默认模型。配置到工具时通过集合预览和事务应用。
- Pi：保留单模型应用方式。

工具默认项可以跟随模板，也可以显式覆盖。所选连接不能使用模板默认模型时，必须为该工具选一个有效默认项。能力未知时不猜测支持的推理强度；先在模型参数中声明能力。

## 操作与生效

在模板中完成多选及工具适配，再点击「配置到工具」。Kimi / DSH 显示该模板选中的模型和启动默认项，保留其他模板与独立配置已管理的条目。

- **保存待应用配置**：持久化模型引用与可选覆盖，不生成档案、不写入原生配置，也不改变当前工具默认模型。
- **预览应用**：解析当前模板和连接，展示模型、移除项、默认项、无法表达的设置及隐藏凭据后的文件差异。
- **应用这些变更**：将整个工具的模型列表通过一次事务写入，以预览中的显式启动默认项生效。
- 每个模型默认继承模板及连接的设置。只覆盖修改过的字段，支持恢复继承；空值明确取消对应继承值。
- 模板保存与工具应用是两个独立动作。编辑模板不会直接切换原生工具配置。

Kimi Code 需要重新加载配置；DSH 的默认项用于新会话，现有会话继续使用自身的选择。应用成功表示原生文件已写入，不表示已实际请求模型 API。

## 数据与原生映射

模板保留原有连接叶节点和 ID，通过可选 `groupId` 聚合同一连接下的模型，新增 `defaultConnectionId` 和 `toolBindings`。旧模板仍可读取，编辑时初始化默认项。复制及迁移会同时重映射连接、分组、默认项和档位引用。

`tool-models.json` 使用版本 1，按工具保存 revision、草稿和已应用档案引用。新条目引用模板 ID、连接 ID；旧的活动档案在未创建集合时作为单项集合展示。没有活动档案时从空集合开始，应用时保留原生文件中的其他条目。

应用时生成常规档案和模板关联，复用已有凭据库引用。关联保存集合自己的能力覆盖，模板更新检查据此解析有效值。集合档案从工具模型列表更新，避免单模板的应用流程覆盖集合设置。

- Kimi 的模型别名与 provider ID 分离，多个模型共享同一 provider。
- DSH 按服务商、端点、协议生成稳定的 provider ID，逐模型写入独立参数。
- 同一路由、同一请求模型 ID 的重复条目被拒绝。
- 移除模型时保留同一 provider 的其他模型；服务商仍被引用时保留凭据。
- 原生导入按模型识别 Kimi 别名和 DSH 多模型条目；回填定位对应模型，避免读取首个模型代替当前项。

## 一致性与恢复

草稿使用 revision 检查并发写入。预览绑定当前用户与会话，十分钟过期；应用前检查集合、模板、档案、凭据库、活动指针及原生文件的指纹。任何依赖变化都要求重新预览。

同一进程内重复提交相同预览返回已完成结果；重启后预览失效，客户端需要重新读取并预览。完整应用将原生文件、档案、活动指针、集合元数据纳入事务日志，失败时回滚。完整恢复点包含集合文件；恢复旧版恢复点时清除当时尚不存在的集合状态。

集合状态比较所有已应用模型与原生配置，不只比较默认模型。现有活动档案的漂移预览和重新应用也包括集合中的其他关联模型。配置文件预览隐藏凭据，DSH 凭据文件中的所有值都被隐藏。

## 范围与验证

集合 HTTP API：`GET/PUT /api/tool-models/:harness`、`POST /api/tool-models/:harness/preview`、`POST /api/tool-models/:harness/apply`，支持 `kimi` 和 `dsh`。入口已集中到模板编辑和应用流程。

集合草稿暂未加入跨机器配置迁移，也没有新增 CLI 集合命令。原有档案、模板及凭据的迁移功能保持原有范围。

隔离测试覆盖多模型保存与应用、独立能力、共享凭据、默认项保持与删除保护、旧档案迁移、模型替换、并发和会话校验、凭据隐藏、漂移及备份恢复。浏览器在独立临时 HOME 中验证了 DSH 多选模板、默认项选择、预览、应用与成功反馈；未修改用户的真实工具配置，也未执行真实模型请求。

Codex 模型目录另在本机 0.153.4 的 `app-server model/list` 中验证：两个自定义模型均可读取，推理档位与默认项正确，无目录解析错误。此验证未发送推理请求，尚未验证其他 Codex 版本。
